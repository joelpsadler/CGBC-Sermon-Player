# Future Engine Notes

## Quote Engine 2.0
- Persist meaningful sermon knowledge and Approved/Featured editorial decisions.
- Routine denials/rejections do not need permanent storage.
- Recommendations should be generated from:
  1. processed transcript baseline,
  2. sermon Info Map context and structure,
  3. Scripture/doctrine/topic signals,
  4. prior Approved/Featured decisions.
- Show a small, high-quality recommendation set for human review.

## CGBC Discover
- Build UI-independent Discover-ready content from the sermon knowledge record.
- UI can be decided later.
- Discover items should retain real sermon timestamps, Scripture, provenance, and links back to source teaching.

## Deep Dive
- Use the same canonical sermon record.
- Preserve fuller sermon structure, Scripture trails, doctrine, word studies, applications, illustrations, and relationships between ideas.

## Possible Pastor Jacob Lannom Author Corpus
- Private, author-facing use only unless separately approved.
- Search Pastor Jacob Lannom's actual teaching across sermons without imitating his voice.
- Preserve exact statements, prepared material, illustrations, applications, definitions, Scripture trails, recurring arguments, doctrine connections, and source history.
- Always distinguish Pastor material from AI synthesis/classification.

## Canonical-file principle
One sermon should have one durable JSON knowledge record.
Generated indexes and UI-specific files should be rebuildable outputs, not manually maintained masters.
